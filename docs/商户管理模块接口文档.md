# 商户管理模块接口文档

> 版本：1.0　适用范围：运营端（平台运营）商户全生命周期管理
> 配套实现：
> - 后端 `controller.MerchantController`（`/merchant/**`）+ `service.MerchantService`（业务与审计）
> - 数据模型 `entity.Merchant`（`t_merchant`）+ `entity.Enterprise`（`t_enterprise`）
> - 安全 `common.CryptoUtil`（AES-256-GCM 加解密/脱敏）+ `config.AppCryptoProperties`（密钥注入）
> - 权限 `common.UserIdentity`（权限矩阵 + 商户可选权限白名单）+ `integration.security.PermInterceptor`（强制校验）
> - 前端 `views/admin/MerchantReview.vue` + `components/merchant/MerchantEditModal|MerchantStatusModal|MerchantPermModal.vue`

## 1. 模块范围

| 子模块 | 能力 | 接口 |
| --- | --- | --- |
| 基本资料管理 | 商户资料查询、增量修改（联动企业工商信息）、注销（逻辑删除） | `GET /merchant/admin/list`、`GET /merchant/admin/detail/{merId}`、`PUT /merchant/admin/{merId}`、`DELETE /merchant/admin/{merId}` |
| 账户状态维护 | 正常(1) / 冻结(2) / 注销(3)，变更需填写原因 | `POST /merchant/admin/status/{merId}` |
| 权限配置 | 商户档可选权限的授予 / 回收 | `GET /merchant/admin/perms/{merId}`、`PUT /merchant/admin/perms/{merId}` |
| 敏感信息 | 税务登记号完整值按需解密查看（写审计） | `GET /merchant/admin/{merId}/tax-reg-no` |
| 入驻审核（已有） | 审核通过 / 驳回、流程跟踪 | `POST /merchant/admin/review/{merId}`、`GET /merchant/admin/review-logs/{merId}` |

## 2. 访问控制

- **运营端护栏**：`AuthInterceptor` 对所有 URI 含 `/admin/` 的请求强制 `role_id=3`（平台运营），越权返回 `403` 并写 `ACCESS_DENIED` 审计日志。本模块全部维护接口均位于 `/merchant/admin/**`，天然受该护栏保护。
- **契约守卫**：`integration.security.MerchantAdminEndpointTest` 通过反射锁定「所有维护接口必须位于 `/admin/` 下」，防止后续重构把管理接口暴露到公开路径。
- **商户自助接口**（`/merchant/my`、`/merchant/license`、`/merchant/tax-proof`、`/merchant/tax-query`）仍由 `@RequirePerm("merchant:manage")` 保护，受商户级授权控制（见第 7 节）。

## 3. 统一响应与错误码

响应体结构（`common.R`）：`{ "code": 200, "message": "操作成功", "data": ... }`

| code | 触发场景 |
| --- | --- |
| 200 | 成功 |
| 400 | 参数校验失败（Bean Validation，返回具体字段提示） |
| 401 | 未登录（`AuthInterceptor` / `PermInterceptor`） |
| 403 | 无权限（非平台运营访问 `/admin/`；或缺少 `@RequirePerm` 声明权限） |
| 500 | 业务异常（`BusinessException`，如「商户不存在」「状态变更必须填写原因」）或服务端异常 |

## 4. 接口详情

### 4.1 商户列表（已有，出口已脱敏）

`GET /merchant/admin/list?reviewStatus=`

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| reviewStatus | int | 否 | 审核状态过滤：0待审 1通过 2驳回；不传为全部 |

响应 `data` 为商户数组（按创建时间倒序），关键字段：

```json
[{
  "merId": 1, "entId": 1, "userId": 3,
  "regType": "公司", "regCapital": 5000000.00, "taxStatus": 1,
  "joinType": "邀约", "reviewStatus": 1, "rejectReason": null,
  "licenseUrl": "/api/uploads/licenses/3_1712345678901.png",
  "taxProofUrls": "/api/uploads/tax-proofs/3_1712345678902.pdf",
  "taxRegNo": "915****00XA",
  "status": 1,
  "permCodes": null,
  "createTime": "2026-10-07 10:20:30"
}]
```

> `taxRegNo` 为脱敏值（前 3 后 4）；`status` 缺省视为 1（正常），`permCodes=null` 表示未显式配置（默认全量授予）。

### 4.1.1 分页查询（管理页表格实际使用）

`GET /merchant/admin/page`

| 参数 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| page | long | 1 | 页码 |
| size | long | 10 | 每页条数 |
| reviewStatus | int | — | 审核状态：0待审 1通过 2驳回 |
| status | int | — | 账户状态：1正常 2冻结 3注销 |
| keyword | string | — | 纯数字按「商户ID 或 企业ID」精确匹配；否则按企业名称模糊匹配 |

响应 `data` 为 MyBatis-Plus `Page`：`{ "records": [...], "total": 128, "size": 10, "current": 1, "pages": 13 }`（`records` 内同样为脱敏后的商户对象）。

> 性能说明：按企业名称检索时先查 `t_enterprise` 得到候选企业ID再按 `ent_id` 集合过滤；**关键词无任何匹配企业时直接返回空页，不触发商户表查询**，避免关键词误输导致全表扫描。

### 4.2 商户详情（已有，聚合视图）

`GET /merchant/admin/detail/{merId}`

响应 `data`：

```json
{
  "merchant": { "merId": 1, "taxRegNo": "915****00XA", "status": 1 },
  "enterprise": { "entId": 1, "name": "华晨建材集团有限公司", "creditCode": "915****00XA" },
  "qualifications": [{ "qId": 1, "qName": "建筑业企业资质证书" }],
  "certReadiness": { "hasLicense": true, "taxProofCount": 3, "hasTaxRegNo": true, "qualificationCount": 1 }
}
```

> `creditCode` 与 `taxRegNo` 均为脱敏值；读取时会顺带把历史明文就地重加密落库（迁移幂等）。

### 4.3 修改商户基本资料

`PUT /merchant/admin/{merId}`　权限：平台运营

请求体（**增量更新，仅提交需要变更的字段**；留空/null 表示不修改）：

```json
{
  "entName": "重庆华晨建材集团有限公司",
  "creditCode": "91500000MA5U0000XA",
  "regType": "公司",
  "regCapital": 8000000.00,
  "taxStatus": 1,
  "joinType": "邀约",
  "taxRegNo": "91500000MA5U0000XA"
}
```

| 字段 | 校验 |
| --- | --- |
| entName | ≤128，联动更新 `t_enterprise.name` |
| creditCode | ≤64，联动更新 `t_enterprise.credit_code`，**加密存储** |
| regType | 仅允许 `公司` / `个体工商户` |
| regCapital | ≥0 |
| taxStatus | 0 未知 / 1 稳定 |
| joinType | ≤16 |
| taxRegNo | ≤64，**加密存储**；传空串表示清空绑定 |

> **掩码防护**：`creditCode` / `taxRegNo` 若提交含 `****` 的脱敏占位值（例如把列表/详情返回的 `915****00XA` 原样回填），服务端直接返回 `500「XX不能提交脱敏占位值，请填写完整内容」`，且**不做任何写入**（敏感字段在方法开头集中校验，避免「商户已改、企业校验失败」的部分写入）。

响应：`{ "code": 200, "message": "商户资料已更新", "data": { ...脱敏后的商户对象 } }`

审计：`MERCHANT_UPDATE`（记录变更字段名，不落敏感明文）

### 4.4 注销商户

`DELETE /merchant/admin/{merId}?reason=长期未经营`　权限：平台运营

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| reason | string | 是 | 注销原因，写入审计日志与 `t_merchant_review_log` |

语义：账户状态置 3（已注销）+ 逻辑删除（`deleted=1`，数据保留可追溯）+ 商户负责人 `role_id` 降级为 1（买家）+ 审计 `MERCHANT_DELETE`。
重复注销返回 500「该商户已注销」。

### 4.5 账户状态变更

`POST /merchant/admin/status/{merId}`　权限：平台运营

```json
{ "status": 2, "reason": "存在违规经营行为，暂停经营权限待核查" }
```

| 字段 | 校验 |
| --- | --- |
| status | 必填，1 正常 / 2 冻结 / 3 注销 |
| reason | 必填（≤200） |

语义：

| 目标状态 | 行为 |
| --- | --- |
| 1 正常 | 恢复正常；商户侧可选权限按档案授权立即生效 |
| 2 冻结 | 商户侧可选权限（`merchant:manage`、`product:publish`）**立即失效**，无需商户重新登录；`role_id` 不变 |
| 3 注销 | 走 4.4 注销逻辑（逻辑删除 + 身份降级） |

审计：`MERCHANT_STATUS_CHANGE`；同时写 `t_merchant_review_log`（action=`status`）。

### 4.6 商户权限配置

**查询**　`GET /merchant/admin/perms/{merId}`

```json
{
  "merId": 1, "status": 1, "configured": false,
  "optionalPerms": ["merchant:manage", "product:publish"],
  "grantedPerms": ["merchant:manage", "product:publish"]
}
```

**保存**　`PUT /merchant/admin/perms/{merId}`（请求体为权限点数组）

```json
["product:publish"]
```

| 情形 | 存储值 | 生效权限 |
| --- | --- | --- |
| 未配置（历史数据） | `null` | 白名单全部（保证存量商户不降权） |
| 提交 N 项 | `"a,b"` | 仅列表内权限点 |
| 提交空数组 | `""` | 无（显式回收全部可选权限） |

白名单外的权限点（如 `admin:all`、`credit:repay`）一律返回 500「不支持的商户权限点」。
审计：`MERCHANT_PERM_CHANGE`；同时写 `t_merchant_review_log`（action=`perm`）。

### 4.7 查看完整税务登记号

`GET /merchant/admin/{merId}/tax-reg-no`　权限：平台运营

```json
{ "code": 200, "data": { "merId": 1, "taxRegNo": "91500000MA5U0000XA", "masked": "915****00XA" } }
```

- 敏感操作：每次调用写入审计 `MERCHANT_TAX_REG_VIEW`（含操作人、时间、客户端 IP、User-Agent）。
- 未绑定税务登记号返回 500「该商户尚未绑定税务登记号」。

## 5. 数据模型与索引

`t_merchant` 新增列（`sql/schema.sql`，全部为**幂等迁移**：新库建表即含，老库按 `information_schema` 判断后 `ALTER`，可重复执行）：

| 列 | 类型 | 说明 |
| --- | --- | --- |
| status | TINYINT DEFAULT 1 | 账户状态 1正常 2冻结 3注销 |
| perm_codes | VARCHAR(500) | 商户授权权限点（逗号分隔，白名单内） |
| tax_reg_no | VARCHAR(255) | 由 VARCHAR(32) 扩长，容纳 `enc:` 密文 |

`t_enterprise.credit_code` 由 `VARCHAR(64)` 扩长至 `VARCHAR(255)`（同上幂等处理）。

新增索引（仅不存在时创建）：

| 索引 | 列 | 用途 |
| --- | --- | --- |
| `idx_merchant_user` | `user_id` | `getByUser` 高频点查（权限判定、我的商户） |
| `idx_merchant_review_status` | `review_status` | 运营端审核状态筛选 |
| `idx_merchant_status` | `status` | 运营端账户状态筛选 |

## 6. 敏感信息加密与脱敏

- **算法**：AES-256-GCM（`AES/GCM/NoPadding`，12 字节随机 IV，128 位认证标签），每次加密使用新 IV，相同明文产生不同密文。
- **存储格式**：`enc:` + Base64(IV ‖ 密文+标签)。带前缀即密文。
- **密钥**：`lanlink.crypto.key`（`application.yml`），生产通过环境变量 `MERCHANT_CRYPTO_KEY` 注入。支持 Base64(32 字节) 密钥或任意口令串（内部 SHA-256 派生）；未配置时回退内置演示密钥并打印告警（仅本地演示）。
- **存量兼容**：读取时按 `enc:` 前缀判断，无前缀的历史明文原样返回；单条记录读取路径（`/merchant/my`、`/merchant/admin/detail/{merId}`）会就地重加密落库，迁移幂等。
- **出口脱敏**：列表、详情、`/merchant/my`、以及资料/状态/权限变更的响应统一走 `CryptoUtil.mask`（保留前 3 后 4），完整明文仅 4.7 接口按需解密返回。
- **审计脱敏**：`MERCHANT_UPDATE` 只记录变更字段名，不落敏感明文。
- **掩码占位值防护**：所有敏感字段写入统一走 `MerchantService.encryptSensitive(raw, 字段名)` —— 归一化（去空格/转大写）→ 校验是否含 `****`（`CryptoUtil.isMasked`）→ 加密。拦截「客户端把脱敏展示值回填提交」导致掩码被当作真实证照号落库（不可逆的数据污染）。前端 `MerchantEditModal` 同步做提交前拦截并提示。
- **出口脱敏一致性**：`/merchant/my`、`/merchant/admin/list`、`/merchant/admin/detail`、资料/状态/权限变更响应、`/merchant/admin/review/{merId}` 全部脱敏，杜绝密文回传前端（密文泄露可被离线分析的场景）。

## 7. 权限判定链路（商户级授权如何生效）

```
AuthInterceptor（登录 + 实时身份识别 + /admin/ 运营护栏）
        ↓
PermInterceptor（@RequirePerm 校验）
   ├─ 非商户身份 / 非白名单权限  → 角色权限矩阵（UserIdentity）
   └─ 商户身份 + 白名单权限      → 商户档案授权（MerchantService.effectiveOptionalPerms）
                                    · perm_codes=null → 默认全量    · status=2/3 → 空集（即时失效）
                                    · 结果按请求缓存（单次请求最多 1 次索引点查）
```

白名单（`UserIdentity.MERCHANT_OPTIONAL_PERMS`）：`merchant:manage`（商户中心/证照/流量）、`product:publish`（商品发布与管理）。

## 8. 操作日志与审计

| action | 触发 | 记录内容 |
| --- | --- | --- |
| `MERCHANT_UPDATE` | 修改商户资料 | 操作人、merId、变更字段名 |
| `MERCHANT_STATUS_CHANGE` | 账户状态变更 | 操作人、merId、冻结/恢复、原因 |
| `MERCHANT_DELETE` | 注销商户 | 操作人、merId、原因 |
| `MERCHANT_PERM_CHANGE` | 权限配置 | 操作人、merId、授权清单 |
| `MERCHANT_TAX_REG_VIEW` | 查看完整税务登记号 | 操作人、merId |
| `IDENTITY_CHANGE` | 注销/审核引发身份升降级 | 用户、方向（buyer ↔ merchant） |
| `ACCESS_DENIED` | 越权访问 | 用户、所需权限、URI |

写操作均通过 `AuditService.record(operatorId, action, detail, request)` 记录，携带客户端 IP 与 User-Agent（`X-Forwarded-For` 优先）。
生命周期动作（状态变更、注销、权限调整）同时写入 `t_merchant_review_log`，供入驻流程跟踪视图展示。

## 9. 性能设计

| 措施 | 效果 |
| --- | --- |
| 新增 `idx_merchant_user` / `idx_merchant_review_status` / `idx_merchant_status` | 高频点查与运营端筛选走索引，避免全表扫描 |
| 状态/权限变更均为单行 `UPDATE` | O(1)，无批量关联更新 |
| 商户授权按请求缓存（`request` attribute） | 单次请求最多 1 次商户档案查询，不与 `@RequirePerm` 次数线性相关 |
| 列表使用 `GET /merchant/admin/page` 服务端分页 + 服务端筛选（审核状态/账户状态/关键词） | 大表不再全量拉取，首屏数据量与内存占用恒定；前端仅渲染当前页 |
| 关键词检索两段式（企业名 → 企业ID集合 → `ent_id in (...)`），无匹配即刻空页返回 | 避免 `LIKE` 全表扫描与无谓查询；命中集合有限 |
| `detail` 聚合保持 3 次点查，不引入多表 join | 详情接口耗时稳定 |
| 加密仅作用于少数敏感列，AES-GCM 单值开销为微秒级 | 对列表接口无感 |

> 说明：本环境未连通 MySQL，运行时压测需在有库的环境执行；建议用 `GET /merchant/admin/list` 与 `GET /merchant/admin/perms/{merId}` 在 1 万商户数据量下做基线，确认耗时在 10ms 级。
