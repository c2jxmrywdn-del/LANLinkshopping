# LANLinkshopping 邮件通道配置（SMTP）

本项目的邮箱验证码接口使用 Spring Boot `JavaMailSender` 通过 SMTP 发送。SMTP 发送只有在服务器、端口、发件账号和 SMTP 密码/授权码都配置完整时才会启用；生产环境不会把验证码写进 API 响应。开发 Profile 在 SMTP 配置不完整时才允许回退到演示验证码。

## Railway 配置（推荐：QQ 邮箱）

在 Railway 项目中打开 **LANLinkshopping 服务 → Variables**，设置以下非敏感参数：

| 变量 | 值 |
| --- | --- |
| `MAIL_HOST` | `smtp.qq.com` |
| `MAIL_PORT` | `465` |
| `MAIL_USERNAME` | 作为发件人的完整 QQ 邮箱地址 |
| `MAIL_SMTP_SSL` | `true` |
| `MAIL_SMTP_STARTTLS` | `false` |

然后在邮箱设置中启用 SMTP 服务，将邮箱服务生成的**SMTP 授权码**设置为 Railway 的 `MAIL_PASSWORD`。不要使用 QQ 邮箱网页登录密码，也不要把授权码提交到 GitHub、写入 YAML 或发送到聊天中。

## Gmail / 其他 SMTP 服务

按邮件提供商要求填写主机、端口和应用专用密码。例如使用 Gmail 常见的 STARTTLS 配置时：

| 变量 | 示例值 |
| --- | --- |
| `MAIL_HOST` | `smtp.gmail.com` |
| `MAIL_PORT` | `587` |
| `MAIL_USERNAME` | 完整 Gmail 地址 |
| `MAIL_PASSWORD` | Gmail 应用专用密码（通过 Railway Variables 单独录入） |
| `MAIL_SMTP_SSL` | `false` |
| `MAIL_SMTP_STARTTLS` | `true` |
| `MAIL_SMTP_STARTTLS_REQUIRED` | `true` |

配置完成并重新部署后，已登录用户通过 `POST /api/user/email-code` 请求邮箱验证码。SMTP 成功发送时 API 不返回验证码；若 SMTP 凭据完整但服务器拒绝连接/认证，接口会报告发送失败，而不会静默改发演示码。

## 生产切换提示

当前 Railway 部署沿用 `dev` Profile 来保留现有演示登录/支付流程。仅配置邮件通道不会自动切换 Profile。真实生产上线前，还需完成短信和支付通道配置并验证登录/下单流程，再将 `SPRING_PROFILES_ACTIVE` 切换为 `prod`，同时关闭模拟支付。不要在缺少其他生产通道时提前切换，以免演示流程中断。
